# 서비스 점검 — 2026-10-05

## 범위와 확인 방법

로컬 웹 앱을 실행해 390×844, 320×568, 1440×900 화면에서 랜딩, 공개 커뮤니티, 감정 풀기, 인증 이동, 준비 중인 결제, 잘못된 경로를 확인했다. 로그인 이후 상담·리포트는 코드로 검토했다. 실제 카카오 인증, 유료 결제, AI 상담 요청 및 데이터 변경은 실행하지 않았다. Firebase 운영 규칙과 Dify 운영 프롬프트는 검증하지 않았다. 모바일 네이티브 앱은 소스만 확인했고 실행하지 않았다.

## 평가

초록색 계열, 둥근 카드, 숲이라는 주제는 일관되고 모바일 랜딩의 정보 구조도 이해하기 쉽다. 비로그인 커뮤니티 열람과 저장하지 않는 감정 풀기는 진입 부담을 낮춘다. 다만 공개 범위, 감정 데이터의 신뢰성, 상담 완료 후 저장 결과가 서비스 안내와 일치하지 않는다. 시각적 장식보다 이 문제들을 먼저 해결해야 한다.

## 최우선 문제

### 1. 비공개 안내와 실제 공개 범위가 일치하지 않음

- `src/store/worryStore.ts`: 공개 기본값과 초기화 값이 `true`다.
- `src/hooks/useCounselingPrompt.ts`: 결과 화면으로 이동하기 전에 기록을 저장한다.
- `src/components/templates/step/StepFive.tsx`: 공개 설정 변경이 메모리 상태만 바꾸고 저장된 기록을 갱신하지 않는다.
- `src/hooks/useContentsData.ts`, `src/utils/contentUtils.ts`, `src/components/pages/Advice.tsx`: 전체 contents를 읽으며 `open === true` 필터가 없다. 클라이언트 코드상 비공개 기록을 제외하지 않는다. 실제 DB 규칙에 따른 접근 가능 범위는 별도 확인이 필요하다.

개선: 기본 비공개, 전송 전 공유 동의, 저장된 기록 ID에 대한 공개 설정 갱신, 공개/개인 데이터의 읽기 경로와 권한 분리. 화면 필터만으로 접근 권한을 대신해서는 안 된다.

### 2. 감정 리포트가 무작위 점수에 기반함

`src/hooks/useWorryManager.ts`에서 감정 점수를 1~5 무작위로 저장한다. Home과 Insight는 6 이상을 긍정 상태로 구분하므로 새 기록에서는 해당 범주에 진입할 수 없다. EmotionChart와 RecentRecords는 4 이상을 긍정 상태로 구분해 같은 기록의 해석도 다르다. Insight는 이 데이터를 'AI 감정 분석'으로 표현한다.

개선: 사용자가 직접 고른 기분을 저장하고 점수 범위·문구를 통일한다. 실제 분석이 연결되기 전에는 AI 분석 표현을 제거하고, 기록이 없는 상태에서 감정 평가를 하지 않는다.

### 3. 인증·상담 횟수 검증이 서버에 없음

`api/chat.ts`는 사용자 인증, 상담 횟수, 입력 길이 검증 없이 외부 AI 요청을 전달한다. 브라우저의 상담 횟수 검사만으로는 직접 API 요청을 막을 수 없다. 인프라 차원의 제한은 확인하지 않았다. `useKakaoAuth.ts`는 `VITE_KAKAO_SECRET_KEY`를 클라이언트에서 사용한다.

개선: 서버에서 인증과 횟수 차감을 검증하고 중복 요청을 처리한다. OAuth 비밀값과 AI 키는 서버 전용 환경변수로 옮긴다. 실제 배포 번들에 비밀값이 포함됐는지도 별도 확인한다.

### 4. 저장 실패를 상담 성공으로 처리함

`useCounselingPrompt.ts`는 기록 저장 실패를 로그로만 처리한 뒤 결과 단계로 이동한다. 이후 StepFour는 상담 횟수를 차감한다. 사용자는 조언과 '공유됨' 안내를 보지만 숲에 기록이 남지 않을 수 있다.

개선: 응답 생성과 기록 저장 상태를 각각 표시하고, 저장 실패 시 재시도 제공. 저장 재시도로 AI 호출이나 횟수 차감이 중복되지 않게 한다.

## 사용자 흐름 개선

| 문제 | 근거 | 개선 |
|---|---|---|
| 상담 소진 후 막힘 | StepFour가 결제를 요구하지만 Credit는 준비 중 화면 | 실제 충전 규칙과 다음 이용 가능 시점 안내, 돌아가기 제공 |
| 자정 충전 안내 불일치 | User는 매일 자정 충전 안내, userStore는 인증 상태 변경 시 UTC 날짜로 갱신 | 한국 날짜 기준으로 이용 시점에도 갱신하고 시점 명시 |
| 로그인 후 원래 목적지 소실 | AuthGuard는 목적지 저장 없이 /auth 이동, 로그인 성공은 홈 이동 | 원래 탭·작성 화면으로 복귀, 인증 확인 중 상태 제공 |
| 본인 글 판단 부정확 | Advice가 displayName으로 작성자 판단, 새 기록에 userId 미저장 | UID로 소유권 연결·판단하고 DB에서도 검증 |
| 오류와 빈 상태 구분 부족 | Advice가 useContentsData의 error를 사용하지 않음 | 오류 안내와 재시도, 빈 상태에는 작성 CTA |
| 상담 시작까지 선택 부담 | 숲 → 상담 대상 → 말투 → 입력 → 결과 | 바로 입력을 기본으로 하고 대상·말투는 기본값과 선택 설정 제공 |
| 결과 화면의 행동 불명확 | '다시 심기', '커뮤니티에서 보기'가 결과 기록의 위치를 분명히 안내하지 않음 | '내 기록 보기' 우선, 추가 상담과 공유는 보조 행동 |
| 커뮤니티 탐색 비효율 | 한 글씩 화살표로 순환, 공유 배너에 동작 없음 | 목록·카테고리·상세 화면, 배너를 작성 버튼으로 연결 |

권장 흐름: 홈의 '마음 기록하기' → 고민 입력 및 직접 기분 선택 → 선택형 상담 스타일 → 비공개 기본값 확인 → 조언 생성 → 저장 성공 확인 → 내 숲의 기록 상세. 커뮤니티 공유는 별도로 동의받는다.

## 디자인 개선

1. 브랜드 통일: 화면은 MindLift, 문서와 페이지 제목은 HELPER/WorryHelper다. 제품명과 로고·제목·인증 문구를 맞춘다.
2. 탭명 구체화: '고민 / 조언 / 풀기'보다 '고민 나누기 / 마음의 숲 / 감정 풀기'가 기능을 예측하기 쉽다. 모바일 너비에 맞춰 최종 명칭을 선택한다.
3. 랜딩 문구: '고민을 키워가요'는 고민이 커진다는 뜻으로도 읽힌다. '고민을 내려놓고 마음의 숲을 가꿔요'처럼 기대 결과를 표현한다.
4. 첫 행동 강화: 네 가지 기능 카드보다 '마음 기록하기'를 먼저 강조하고, 조언 예시를 보여준다. 공개 여부·기록 보관 안내도 진입 시 이해할 수 있게 한다.
5. 글자 위계: 9~11px 보조 문구와 옅은 회색이 많다. 중요한 설명은 12~14px 수준으로 키우고 대비를 높인다. 이번 점검에서는 색 대비 수치를 측정하지 않았다.
6. 접근성: 상단 아이콘 버튼의 접근 가능한 이름이 없고 로고는 클릭 가능한 p다. 버튼/링크 의미 구조, 현재 탭의 aria-current, 키보드 포커스, 모달 포커스 관리, 움직임 감소 설정을 적용한다.
7. 감정 풀기 톤: 초기 화면의 욕설·손가락 이모지 예시는 차분한 랜딩과 분위기 차이가 크다. 중립적인 예시와 선택형 강도를 제공한다. 텍스트에 따른 시각 강도 처리가 있으므로 '분석 안 함'은 'AI 분석·서버 저장 없음'처럼 범위를 구체화한다.
8. 데스크톱: 1440px에서도 본문이 480px로 고정된다. 모바일 중심 제품이라면 의도된 선택일 수 있다. PC를 지원하려면 탐색과 콘텐츠를 분리해 여백을 활용한다.

## 모바일 앱 별도 확인

`mobile/`은 웹과 달리 지도·고민·답장 중심 구조다. `mobile/data/seed.ts`의 데모 데이터와 `mobile/app/auth.tsx`, `compose.tsx`, `worry/[id].tsx`의 실제 인증·작성·답장 저장 TODO를 확인했다. 현재 연결된 기능과 데모 기능을 구분해야 한다. 모바일 앱을 실행한 시각·상호작용 검증은 하지 않았다. mobile README의 Expo 실행 안내도 현재 React Native CLI 기반 package.json과 맞지 않는다.

## 검증 결과

- 웹 프로덕션 빌드: 통과. 번들 경고가 있어 성능 측정은 별도 필요하다.
- 테스트: 27개 중 24개 통과, 상담 훅 테스트 3개 실패. 실제 외부 fetch와 timeout 오류가 발생해 테스트 격리도 점검해야 한다.
- 린트: flat config와 --ext 옵션 충돌로 실행 실패. 코드 규칙 통과 여부는 확인할 수 없다.
- 브라우저: 비로그인 커뮤니티 열람, 감정 풀기 입력·외치기, 보호 화면의 인증 이동 확인. 390px 홈은 가로 넘침 없음. 320px 감정 풀기 입력과 버튼은 화면 안에 배치됨.
- 검증 한계: 로그인 사용자 상담 완료, 실제 OAuth, 네이티브 앱, 운영 DB 규칙, 배포 서버, 실제 모바일 키보드와 스크린리더는 미검증.

## 권장 작업 순서

공개 범위·감정 점수·서버 인증 → 저장 성공과 실패 처리 → 상담 소진·로그인 복귀 → 탭과 작성 흐름 → 타이포그래피·접근성 → 커뮤니티 탐색·PC 화면. 변경 후에는 '비공개 글이 다른 사용자에게 읽히지 않는지', '공개 설정이 새로고침 후 유지되는지', '저장 재시도가 중복 차감되지 않는지'를 우선 검증한다.
