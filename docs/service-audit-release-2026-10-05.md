# 서비스 점검 후 반영 및 검증

초기 발견 사항은 `service-audit-2026-10-05.md`에 기록했다. 이번 변경은 웹 서비스 기준이며 네이티브 앱은 별도 데모임을 명확히 표시했다.

## 반영

- 기본 비공개, UID 기반 소유권, 공개 데이터와 개인 기록 경로 분리, 브라우저 DB 쓰기 차단.
- 서버 ID 토큰 검증, 한국 자정 기준 일일 10회 한도, 중복 생성·저장 방지, 삭제 기록 재생성 방지.
- OAuth 비밀값 서버 이동, state 검증, 로그인 이후 원래 화면 복귀.
- 고민·기분 입력을 한 화면으로 정리하고 저장 확인·재시도·공개 전환·삭제 연결.
- 홈, 공개 고민 검색/분류/상세, 실제 사용자 선택 기반 기분 리포트, 모바일/데스크톱 내비게이션 정리.
- 접근성 이름, 입력 레이블, 키보드 포커스, 삭제 확인 대화상자, 모션 감소, 오류·빈 화면 개선.
- 준비 중인 결제 화면을 실제 무료 이용 안내로 변경.
- 미사용 무거운 의존성과 단계 제거, 빌드 타입 검사, CI 추가, 로컬에서 같은 서버 API 실행.
- 서버리스 Firebase의 빈 로컬 캐시에서 잠금 해제가 누락되는 문제를 미리보기 테스트로 재현하고 수정.

## 데이터 이전

기존 57건 중 소유자 인덱스가 일치한 38건을 비공개로 이전했다. 소유자가 불명확한 19건은 이름으로 추측하지 않고 보호된 기존 경로에 보존했다. 기존 데이터와 규칙 백업은 Git과 배포에서 제외한 `.local-backups`에 보관한다. 과거 무작위 기분 값은 통계에서 제외한다.

운영 Firebase 규칙 배포 완료. 인증 없는 기존 전체 기록·개인 기록 읽기는 401, 동의한 공개 데이터 읽기는 200을 확인했다. 과거의 공개 규칙으로 롤백하지 않는다.

## 검증

- 웹 자동 테스트 43건: 인증, 입력, 이용량, 재시도, 중복 요청, 삭제/공개 권한, 잠금, 한국 자정, 기분 정규화 및 로그인 복귀 경로.
- 웹 lint, 타입 검사, 운영 빌드 통과. 네이티브 데모 lint와 타입 검사 통과.
- 별도 임시 Firebase 테스트 계정으로 실제 서버 API와 브라우저 작성, 공개/비공개 변경, 댓글, 응원, 삭제 및 새로고침 후 상태 확인.
- 실제 Dify 일반 조언 생성 및 비공개 저장 성공, 위기 입력은 외부 호출 없이 안내 제공.
- 320/390/1440px 화면 가로 넘침 없음, 삭제 대화상자 초기 포커스와 Escape 동작 확인.
- 운영 번들에서 Dify 키, 카카오 비밀값, 서비스 계정 JSON 및 개인키 표식 0건.

카카오 공급자 화면에서 실제 사용자로 새 OAuth 로그인을 끝내는 작업은 수행하지 않았다. OAuth 시작/콜백 오류 및 state 보호는 확인하며, 공급자 설정 변경 없이 기존 OIDC 연결을 사용한다. 네이티브 앱의 실기기 실행·스토어 배포는 이번 웹 배포 범위에 포함하지 않았다.

## 남은 유지보수 항목

npm audit는 웹 의존성에 17건(높음 9, 보통 8)을 보고한다. 주로 사용하지 않는 Firebase Firestore/gRPC 패키지, Tailwind 빌드 경로 및 Firebase Admin의 클라우드 패키지 하위 의존성이다. 강제 수정은 Firebase 다운그레이드나 Tailwind 4 전환을 요구하므로 일괄 적용하지 않았다. 네이티브 데모에도 기존 의존성 경고가 있으며 별도 업그레이드가 필요하다. 예전 배포에서 사용했던 브라우저 노출 가능 OAuth/Dify 자격 증명은 공급자 콘솔에서 교체해야 한다. 현재 배포에는 서버 전용으로 전달한다.
